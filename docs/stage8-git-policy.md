# 第八階段 Git 保存與發布規則

確認日期：2026-10-27。來源：使用者於本對話明確授權。
本文件取代先前所有「不自行 commit／push 第八階段變更」的限制。
完成第八階段工作、驗證與交接後，自動 commit／push 至既有 origin 的
當時開發分支，不需再次詢問。分支須於發布時重新核對，不固定假設為 main。

## 提交前檢查

1. 核對目前分支、git status、diff 與遠端狀態。
2. 只提交第八階段相關原始碼、建置設定、測試、必要證據與文件。
3. 明確列出 staging 路徑；不直接 git add 全部。保留無關測試、未提交修改
   及衝突副本，尤其不可將既有 UART／PPK2 或其他工作自動歸入第八階段。
4. 排除密鑰、憑證、暫存檔及不應入庫的大型產物。
5. 更新適用的 README、VALIDATION、docs/handoff.md、當前機器紀錄及 HIL；
   清楚區分已實作、已驗證、未通過、待人工確認與尚未測試。
6. 核對文件中的映像 SHA、組態與測試結果。不把舊映像證據記為新映像通過。

## Commit／Push

1. 驗證達成本階段範圍後，以清楚描述最終內容的 commit 保存並正常 push。
2. 有阻礙或測試失敗時，允許保存並推送可回復的 WIP checkpoint；commit
   與交接必須明確標示未完成項目，不宣稱階段驗收通過。
3. 基準 tag 依第八階段原 prompt 指定建立與推送；不移動、覆蓋既有 tag，
   不自行猜測尚未指定的 tag 名稱或基準指向。
4. 第八階段驗收 tag 僅在適用驗收完成後建立；未完成時不建立通過標籤。
5. 禁止 force push、覆寫遠端歷史、清除無關本機內容。
6. 遠端有新增提交時，先檢查差異；不自動解決有歧義的衝突。
7. 認證、網路或衝突阻擋推送時，保留本機 commit，回報阻礙；不宣稱遠端同步。

## 發布核對與回報

1. push 後重新讀取遠端分支 SHA，確認與預期本機 HEAD 一致。
2. 回報分支名稱、commit SHA 與摘要、新增 tag 及其指向、遠端同步結果、
   未納入提交的檔案類別、未完成驗證與剩餘限制。
3. 不為記錄一次發布而反覆增加純發布紀錄 commit；最終 commit／push
   結果可直接在回覆中交接。適用交接文件於功能／WIP commit 前整理完成。
4. 結束時維持板卡 off/debug、UART 關閉，回報板上映像與組態；Git 操作
   不觸發額外硬體測試或供電操作。若板卡已斷電，註明最後已驗證狀態與
   目前供電紀錄，不把歷史狀態當作重新量測。
5. 完成第八階段後停止，不自動加入提醒、持久保存或 NFC 功能。

本次更新僅保存上述發布授權與規則，不代表第八階段功能已實作或驗收完成。
第八階段的具體功能範圍、基準 tag 名稱與適用驗收項目依其實作 prompt。
